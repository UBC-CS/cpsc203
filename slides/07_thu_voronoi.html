Can we do better? Do we need to “visit” (do something for) every pixel? Yes: At a minimum we need to write out a colour for that pixel. So, we probably can’t avoid \(O(n)\). But what about the dependence on number of centers? Can we avoid doing something for each pixel-center combination?

Can we do better?

  • Starting at each center, fill in the immediate neighbours.
  • Then fill in the neighbours of the neighbours.
  • Repeat until all pixels are filled.
  • Each pixel is visited just once.
  • But how do we know which pixel to fill next?
    • We want to fill all the 1-neighbours, then all the 2-neighbours, etc.
    • We know that the 1-neighbours are the neighbours of the centers.
    • We know that the 2-neighbours are the neighbours of the 1-neighbours.
    • Can we arrange to see the centers first, then their neighbours, then their neighbours, …?

Data Structure: Queue

To implement the fill we use a datastructure called a queue.

Operations on a queue:

  • enqueue(d): places data d at the “end” / “bottom” of the queue.
  • dequeue(): removes and returns the element at the “start” / “top” of the queue.

How does the queue differ from the stack you were exploring in the lab?

A queue is a generic name for a data structure with this behaviour, and enqueue and dequeue are generic names for the operations that you perform on this data structure.

You will actually implement a queue in Python using the deque data structure from the collections module, and the methods for enqueue and dequeue will have different names.
