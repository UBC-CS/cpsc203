Analysis (Queue-based Version)

  1. Read image: \(O(n)\)
  2. Choose centers: \(O(dn)\)
  3. Build new image:
    1. enqueue the centers.
    2. while queue not empty:
      1. \(v\) = dequeue.
      2. for each valid neighbour \(w\) of \(v\):
        • process \(w\).
        • enqueue \(w\).
  4. Write out new image: \(O(n)\)

Size of the image: \(n\)
(\(n =\) width \(\times\) height)

Density of centers: \(d\)

Number of centers: \(dn\)

Show \(O(n)\): Consider a single pixel

  • When it is noticed as a neighbour (by a constant number of possible neighbours):
    • Determine if it is valid: constant.
    • Assign a center: constant.
    • Assign a colour: constant.
    • Enqueue: constant.
  • Wait on queue: Unknown, but accounted by pixels ahead of it in the queue.
  • When it is dequeued:
    • dequeue: constant.
    • determine neighbours: constant.
  • Pixel is never worked on again.

Each pixel has a constant amount of work associated with it, so \(O(n)\).

Analysis Continued: The Big Picture

How does the execution time of these algorithms compare?

  • The loop-based version is \(O(dn^2)\), where \(0 < d < 1\).
  • The queue-based version is \(O((d+1)n)\).
    • We did a lot of work for each pixel removed from the queue.

General Comments on Complexity Analysis in Computer Science

When comparing two algorithms, complexity analysis in computer science emphasizes the eventual winner as the problem size grows arbitrarily large.

  • So \(O(n^2)\) is worse than \(O(n)\) regardless of the hidden constants.

Occasionally this approach proves wrong for practical problems.

  • Computational complexity of matrix multiplication of two \(n \times n\) matrices:
    • Naive / standard approach: \(O(n^3)\).
    • Strassen’s algorithm can achieve \(O(n^{\log_2 7}) \approx O(n^{2.807})\).
    • Best complexity (as of August 2026) is \((O^{2.371177})\), but is totally impractical.
  • On modern machines, memory transfer time is often the limiting factor.
  • Strassen’s algorithm uses “divide and conquer”.
  • It requires fewer multiplications but many more additions / subtractions; however, notice that the latter two are \(O(n^2)\) on matrices.
  • It becomes effective as \(n\) gets into the hundreds, although it does have reduced numerical stability.
  • Matrix size needed for even more efficient algorithms to win is too large to fit into current memory (“galactic algorithm”).
  • For many algorithms, computational and memory transfer effort are linearly proportional; however, sometimes there is a version of the algorithm which does more computation while requiring less memory transfer.

Voronoi Diagram: Example of Invariant

Complexity analysis required that no pixel appear in the queue more than once.

  • Example of an invariant: A property which always holds true for an iteration of a loop, an execution of a function / method, or perhaps a whole object or program.
  • In this case:
    • We initialize a flag processed for each pixel to False.
    • We only add the centers and considered neighbour pixels to the queue.
    • We only consider neighbour pixels if processed is False.
    • We only add a center or considered neighbour pixel to the queue after we set processed to be True for that pixel.

No longer easy to determine if the algorithm produces the correct result or even terminates. (See voronoi_deque_failures.py in Class Activity: Voronoi Art Fast.)

  • What happens if pixels can appear more than once?
  • What happens if we do not visit every pixel?
  • Is visiting every pixel exactly once sufficient for correctness?

Proof of correctness is hard (and may be impossible)!

  • If you stick with simple patterns (such as those from CPSC 103 / 110), it may be easier to prove correctness.
  • Mutation makes correctness proofs much harder.
  • Test, test, test…

If pixels can appear a fixed number of times, then it will terminate but possibly be incorrect.

If we consistently omit some neighbours, then some pixels will not be visited; however, even visiting every pixel once does not guarantee correctness.

Proving that an arbitrary program will terminate is impossible.

Testing does not prove correctness. But it is much better than nothing.
